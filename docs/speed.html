How fast is Brisk, measured.

We load the same ten ad-heavy websites with Brisk's ad blocking off, then on, and record how long pages take, how much processor time they burn and how much memory they hold. These are the results, and how we got them.

Blocking ads makes pages faster

Same browser, same sites, same PC. The only difference is whether ads and trackers are allowed to load.

Sleeping tabs give memory back

Ten sites open, then left alone for ten minutes with Brisk's default sleep settings. Tabs in the background step down until they hold almost nothing; the one you're looking at is never touched.

Small where it counts

  • 0.34 msto check a request against the filter lists, on average
  • 37 MBused by Brisk's own process; the rest belongs to the pages you open
  • 67ads and trackers blocked on an average run of the ten sites
  • 7.3 MBinstaller, because the web engine is already part of Windows 11

How we measured

Sites
cnn.com, bbc.com/news, theguardian.com, dailymail.co.uk, forbes.com, weather.com, sanook.com, thairath.co.th, pantip.com and kapook.com, loaded one after another in fresh tabs.
Page load
From opening the tab until the page reports it has finished loading, timed inside Brisk. Each run then waits five more seconds for late ads before memory is read.
Processor time and memory
Processor time is the total used by Brisk and its web engine processes while loading. Memory is private bytes of all those processes with every site still open.
Runs
Three runs with ad blocking off and four with it on, on 8–9 November 2026; the figures are the averages of those runs. The sleep test is one run with ten idle minutes.
Computer
Intel Core i5-11400F, 32 GB RAM, Windows 11, Microsoft Edge WebView2 Evergreen runtime, home broadband.

What about other browsers?

We haven't run Chrome, Edge or Firefox through this test yet. When we do, their numbers will appear here, measured the same way on the same sites. Until then we only publish what we measured.
